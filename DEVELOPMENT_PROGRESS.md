# F1Z PRIME — склад номеров: прогресс

## Что уже реализовано (backend, протестировано)
- **Автоопределение страны** по международному коду через `phonenumbers` (libphonenumber). США/Канада и другие
  страны, делящие код, различаются по региону; неоднозначные коды (`+1`, `+7`, `+44`) не угадываются — возвращается
  список вариантов, и администратор выбирает страну. Нормализация в E.164 (удаление пробелов/дефисов/скобок, `00`→`+`).
- **Таблица `phone_inventory`** (миграция 0008): `phone_e164` (уникальный), `country_iso2/name`, `product_id`,
  `status` AVAILABLE/RESERVED/SOLD/DISABLED, `reserved_order_id`, `sold_order_id`, `batch`, `added_by`, `note`,
  `created_at/reserved_at/sold_at`. Индексы по (product,status), (country,status), reserved/sold order.
- **Остатки выводятся из реальных записей** (`available_count`), не хранятся отдельным счётчиком: при добавлении,
  продаже, отмене и удалении `product.stock` пересчитывается из числа AVAILABLE.
- **Добавление номеров**: по одному (с предпросмотром определённой страны), массово списком, из TXT/CSV
  (берётся первый столбец). Дубликаты (в файле и в БД) и некорректные номера отбрасываются; импорт возвращает
  `добавлено / дубликатов / некорректных / неоднозначных`.
- **Атомарная выдача после оплаты**: при создании заказа номер резервируется `SELECT FOR UPDATE SKIP LOCKED`,
  при подтверждённой оплате — продаётся и привязывается к заказу; один номер не может достаться двум покупателям,
  нельзя выдать до оплаты, нельзя выдать номер другой страны, при отмене/истечении номер возвращается в пул.
  Выданный номер виден покупателю в «Мои покупки» (`delivered_items`) с кнопкой копирования.
- **Admin API `/api/admin/phones*`**: detect, add, bulk, list (search/country/status/пагинация), summary
  (всего/доступно/зарезервировано/продано + по странам + последние добавления/продажи), history, export.csv,
  patch (disable/note), delete. Права: чтение `products.view`, изменение `products.stock`.
- **Проверка владения (каркас, только мок)**: `VerificationProvider` + `MockVerificationProvider` (фиктивные
  коды `TEST-xxxxxx`), статусы WAITING/RECEIVED/APPROVED/EXPIRED/FAILED, журнал событий, TTL, лимит попыток,
  защита от повторного решения. Включается настройкой `phone_verification_enabled` (по умолчанию выкл.) и
  НЕ блокирует автоматическую выдачу номера. Экран владельца: список/детали (заказ, страна, статус оплаты,
  покупатель), получить мок-код, «Подтвердить»/«Отклонить». Реальные коды Telegram и `.session` не читаются.
- **Админ-интерфейс «База номеров»** (`admin/src/pages/Phones.tsx`, в навигации под «Товары», права
  `products.view`/`products.stock`): вкладки «Обзор склада» (итоги + остатки по странам + последние
  добавления/продажи), «Добавить номер» (живой предпросмотр определённой страны, выбор при неоднозначном
  коде), «Массовый импорт» (drag-and-drop TXT/CSV + textarea + отчёт добавлено/дубликаты/некорректные/
  неоднозначные), «Все номера» (поиск, фильтр по стране/статусу, пагинация, копирование, отключение,
  удаление, экспорт CSV), «Страны» (таблица остатков), «История продаж», «Проверки» (экран владельца:
  заказ/страна/статус оплаты/время, «Подтвердить»/«Отклонить»/«Связаться с покупателем», журнал действий,
  маска кода, автообновление). Остатки и счётчики берутся из API (реальные записи БД).
- **Mini App**: выданные номера показываются в карточке заказа (`delivered_items`) под заголовком
  «Ваши номера» с кнопкой копирования; метка выбирается по новому полю `delivered_kind` (`phone`/`secret`).

## SMS-активации (resilient engine, коммиты 0009…22160f6)
Реализован отказоустойчивый модуль продажи виртуальных номеров и доставки кодов (интегрирован в
существующие users/orders/ledger, без дублирующих таблиц):
- **Миграция 0009** (аддитивная): `sms_activations` (полная машина состояний + аренда lease_owner/
  lease_generation + частичный уникальный индекс «одна активная на пользователя» + уникальный
  activation_id) и `delivery_outbox` (PENDING/SENT/UNKNOWN/FAILED, dedupe_key). Модели + конфиг
  (`sms_activate_api_key`/`base_url`, ключ только в .env).
- **services/sms.py**: `ActivationProvider` (ABC) + `MockActivationProvider` (тесты) + `SmsActivateProvider`
  (адаптер sms-activate.org). buy(): списание через ledger + резерв под уникальным индексом (вторая
  активация → 409) + getNumber; таймаут → сверка active list, привязка только при однозначном совпадении,
  иначе `RECONCILIATION_REQUIRED` (не угадываем). claim_due()/poll_one(): аренда с проверкой
  lease_generation (защита от «зомби»-воркеров). `STATUS_OK:код` → сохранение + outbox; истечение →
  TIMEOUT; все возвраты — refund-once. Outbox: неопределённая отправка → UNKNOWN (предупреждение+аудит
  перед повтором), явный отказ API → FAILED.
- **worker.py**: `task_sms_poll` (аренда+опрос) и `task_sms_outbox` (доставка) в PERIODIC.
- **tests/test_sms_activation.py**: 7 тестов (покупка/списание/одна-активная, код+outbox, устаревшая
  аренда, таймаут-возврат, отмена-возврат, reconciliation, outbox UNKNOWN→FAILED). Сюита **159 passed**.
